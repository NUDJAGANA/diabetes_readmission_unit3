# Project Plan and Workflow

## Purpose

This project analyses diabetes-related hospital readmission data and communicates findings through a Streamlit dashboard and prediction simulator. It is intended for educational analysis, not clinical decision-making.

## Project phases and evidence

| Phase | Work and evidence | Status |
|---|---|---|
| Define the project | Document the project purpose, intended audience, questions and hypotheses in the README. | Refer to the README. |
| Source and prepare data | Record the dataset source, licence, coverage and limitations. Use the project’s existing data preparation and analysis files. | Existing project work; refer to the README and notebooks. |
| Analyse and build | Create the analysis, dashboard, charts, filters and prediction simulator. | Existing project work. |
| Align the prediction flow | Prepare a model that accepts the six inputs in the prediction form and update the app to use it. | Completed and checked by running the training script and prediction simulator. |
| Evaluate and gather feedback | Record held-out model metrics, the exploratory subgroup audit, the default-input prediction check and the external reviewer’s feedback. | Checks completed; limitations are documented in the ethics and reflection report. |
| Document and publish | Keep the README, ethics and reflection report, project plan and workflow diagram easy to find in the public repository. | Add and commit this plan and diagram; check that the README links to them. |
| Maintain and re-evaluate | Check the app and its outputs after changes. Repeat suitable performance and subgroup checks if the data or model changes. Review privacy and ethical risks before publication. | Future work; no ongoing monitoring is claimed. |
